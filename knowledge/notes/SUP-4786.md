## Problem

KnitWell Group (JIRA tag `[KWG]`, all four brands LOFT, LOS, ANN and ATFS),
QA. In Assortment Build → Style Review → **Style Edit - Size Concept** →
**Price & Cost**, a planner picks a Ticket Price Override (for example
149.00). Nothing is saved: Final Ticket Price stays at the Ticket Price
($160.00 in the LOFT example: style 786335, style color 533123), and the
override cell shows **"$NaN"**. In the browser's Network tab, only a
`lifecycleParams` POST fires, with no pivot3 or redecorate call. A planner
cannot set a channel-specific price, so the plan keeps using the original
ticket price.

The ticket bundles three separate defects. The first two have to be fixed
together, and the third only affects the display:

1. **Save fails:** the dropdown sends a number into a text attribute (config).
2. **Dropdown 500:** once (1) is fixed, the option list fails to load because
   of a NULL blank row (ETL). This was found while fixing (1).
3. **"$NaN" display:** an empty override shows as "$NaN" (frontend regression,
   with a config workaround).

## Diagnosis path

- **What the ticket got wrong about the network calls.** The `lifecycleParams`
  POST **is** the save call. The section's `actions.patch.clientHandler` is
  `planningParams`, and in `assortmentui`
  `StyleEditSection.handleCellValueChange` that handler falls through to
  `updateLifecycleParams` (`POST /api/assortment/lifecycleParams`). The column
  has `refreshSectionAfterEdit: true`, so after an edit the section is
  re-fetched. No pivot3/redecorate call is expected.
- **The save path has no pivot and no model.** The save path is: viewdefn column →
  `updateLifecycleParams` → darwin `AssortmentController.updateLifecycleParams`
  → `ModificationPipelineFacade.runEdit` (validate → write → sync to CH →
  queue replan, in one PG transaction) → `UPDATE
  <brand>_ma_stylecolorchannelattributes SET ccticketpricechannel_override_txt
  = …`. Postgres triggers then derive the numeric override and the price band.
  darwin copies the row to ClickHouse `<brand>_ma_stylecolorchannelattributes_tbl`.
  The model and pivot `StyleChannelReview` are used only to read the data back.
- **Ruled out:**
  - **Triggers:** no lock or revert trigger touches the override columns. The
    trigger and function are identical in all 4 brand schemas
    (`customers/KW/db/README.md`, `knowledge/db-trigger-matrix.md`).
  - **CH sync lag:** darwin reads these cells from PG.
  - **The price itself:** `149.00` is a valid value.
  - **Config drift between brands:** the viewdefn is byte-identical in all
    4 brand repos (blob `33cda33` before the fix, `26c63f4` after). In
    `loft-configs` it was last changed on 2025-07-29 (`b902f07`), so this is
    not a recent config regression.
- **Root cause 1: type mismatch between the dropdown source and the save target (config).**
  In `uidefn/view/AssortmentStyleEditSectionPriceAndCostSizeConcept.viewdefn`,
  the "Ticket Price Override" column saves into
  `dataIndex: attribute:ccticketpricechannel_override_txt:id` (line 32). That
  attribute is **String** (`conf/M_Meta.conf:733`). But its options came from
  `dataApi …/validValues/one?…&ids=ccticketpricechannel` (line 36), which is a
  **Float** attribute (`M_Meta.conf:731`). darwin types each option `id` by the
  attribute's data type (`DataTypeModel` uses `Float.parseFloat` for Float and
  `String.valueOf` for String), and the frontend posts `value: option.id`.
  So picking 149.00 posts `{"ccticketpricechannel_override_txt": 149}`, a
  number. For a STRING column, darwin's `ColDesc.bindInput`
  (`assortment/src/main/java/com/darwin/metav2/ColDesc.java`) does
  `(String) o`. That throws `ClassCastException`, which is re-thrown as
  *"failed to cast input for column: ccticketpricechannel_override_txt this
  may be a configuration issue"*. The whole edit rolls back. The override
  stays NULL, no trigger fires, and Final Ticket Price stays at the Ticket
  Price. The Master view uses the same `ids=ccticketpricechannel` URL without
  problems because there it saves into `ccticketpricechannel`, which is also
  Float (`AssortmentStyleEditSectionPriceAndCostMaster.viewdefn:22-30`). The
  Size Concept override most likely copied that URL, though git history does
  not record it (inferred).
- **Root cause 2: the NULL blank row in valid values (ETL, exposed by the fix for 1).**
  After `ids=` was pointed at `ccticketpricechannel_override_txt`, the
  dropdown call returned HTTP 500 `java.lang.NullPointerException: Tuple has
  null: [null, null]`. darwin `MemberBasedValidValuesFacade.loadValidValues`
  runs `SELECT attributekey, attributevalue FROM <brand>_v_memberbasedvalidvalues
  WHERE membertie = :tie AND attributeid = :id` and wraps each row in
  `IdentTuple.of(key, value)`, which rejects NULL (`model/tuple/Tuple.java`
  `validate`). The ETL builds a blank option for this attribute as `'' / ''`
  in Vertica (`vsql/daily/070_valid_values.sql:1555-1558`; intraday
  `vsql/intraday/003_rebuild_lookups.sql` ~L1500). On the way to Postgres it
  becomes NULL in two steps:
  - The export `sed` (`bash/daily/09_pg_export.sh:13`) strips quotes from
    empty fields (`s/|""|/||/g`, `s/|""$/|/g`).
  - `\copy … DELIMITER '|' CSV HEADER` (`pgsql/daily/load_pgsql.sql:122`)
    reads an unquoted empty field as NULL.

  The load then repaired NULLs only for `membertie`. Observed in LOFT QA PG:
  two rows had NULL `attributekey` and `attributevalue`, one for
  `ccticketpricechannel_override_txt` (indx 51757) and one for
  `sty_size_concept_types` (indx 29). The old `ids=ccticketpricechannel` list
  has no blank row, and no screen had requested the `_txt` list before, so
  the bad row had never come up.
- **Root cause 3: "$NaN" display (frontend regression).** With no override,
  the `_txt` column is NULL. Style Edit's `valueGetter` turns that into `''`,
  and the `usMoney` renderer formats it with `numbro('').format('$0,0.00')`,
  which gives "$NaN". Before frontend commit `33d4e8f53` (INT-6200,
  2026-09-02), Style Edit text renderers went through `NonFrameWorkToS5Renderer`,
  which blanked NaN. That commit moved formatting into a `valueFormatter`
  (`StyleEditSection.tsx` ~L1222-1229) without the guard. So "$NaN" doesn't
  mean the value reverted. It is how an empty override looks.

## Fix

Branch `SUP-4786` in all 8 KW brand repos, one commit each, pushed.
Config branches are 1 commit ahead of `planning_strategy`. ETL branches are 1
commit ahead of `etl_assortment_planning_upgrade` (30–34 ahead of
`etl_assortment_planning`).

**Config: `uidefn/view/AssortmentStyleEditSectionPriceAndCostSizeConcept.viewdefn`**
in `loft-configs` (`3af469b`), `los-configs` (`90f3776`), `ann-configs`
(`2028c24`) and `atfs-configs` (`202fa25`). The change is identical in all 4,
and the resulting blob is `26c63f4`:

```diff
       "text": "Ticket Price Override",
       "dataIndex": "attribute:ccticketpricechannel_override_txt:id",
       "editable": true,
       "inputType": "validValues",
       "dataApi": {
-        "url": "/api/attribute/validValues/one?appName=Assortment&ids=ccticketpricechannel"
+        "url": "/api/attribute/validValues/one?appName=Assortment&ids=ccticketpricechannel_override_txt"
       },
-      "renderer": "usMoney",
+      "renderer": "text",
       "allowEmptyOption": true,
       "refreshSectionAfterEdit": true
```

- **Line 36 (`ids=`):** the options now come from the String attribute the
  field saves into, so the UI posts `"149.00"` as text. Both valid-value sets
  are built from the same price list (`<brand>_in_bus_pricebandlookup` in
  `070_valid_values.sql`), so planners see the same price points.
- **Line 38 (`renderer`):** with `text`, the stored value is shown as is. The
  trigger already saves the text as `$149.00`, and an empty value shows as
  blank instead of "$NaN". `text` is also a key in the frontend's
  Excel-export renderer map, so the cell exports as a string.

**ETL: `pgsql/daily/load_pgsql.sql`, `pgsql/weekly/load_pgsql.sql`, `pgsql/intraday/load_pgsql.sql`**
in `etl-loft-batch` (`300da28`), `etl-los-batch` (`ff14041`), `etl-ann-batch`
(`045f976`) and `etl-atfs-batch` (`ab7c2af`). Two lines go right after the
existing `membertie` clean-up, inside the same load transaction, using each
brand's table prefix:

```sql
update <brand>_v_memberbasedvalidvalues set membertie='' where membertie is null;        -- existing
update <brand>_v_memberbasedvalidvalues set attributekey='' where attributekey is null;    -- added
update <brand>_v_memberbasedvalidvalues set attributevalue='' where attributevalue is null; -- added
```

The fix has to be in all three batches, because daily, weekly and intraday
each delete and fully reload the table. Any one of them would bring the NULL
row back. The fix goes after the load, not in the export, because the export
`sed` turns empty fields into NULL on purpose so that empty number and date
columns load correctly in every table. A post-load clean-up also covers any
other attribute with a blank row, such as `sty_size_concept_types`.

**Deploy order:** ETL/data first, then config. If the config change lands
first, the dropdown returns 500 until the NULL row is fixed. LOFT QA was
corrected by hand in the meantime with a one-off
`UPDATE … SET attributekey='', attributevalue='' WHERE attributekey IS NULL AND attributevalue IS NULL`.
Other brands' QA need the same one-off update, or a batch run after the ETL
deploy.

**Not in this ticket:** the platform fix for "$NaN", which restores the
empty/NaN guard in the Style Edit `valueFormatter` in `assortmentui`. It is
meant to be raised as a separate frontend (INT) ticket. Its status is not
recorded locally.

## Knowledge gained (techno-functional)

**Technical:** in a Style Edit `inputType: "validValues"` column, the saved
value is the selected option's `id`. darwin types that `id` by the `dataApi`
attribute's M_Meta type, not by the `dataIndex` attribute's type. If a
Float-typed list feeds a String column, darwin's `ColDesc.bindInput` throws
`failed to cast input for column: <col>` and rolls back the whole edit. The
UI shows nothing beyond the field staying unchanged. In KW, the override is
stored twice:
- `ccticketpricechannel_override_txt` (String) is what the user edits.
- `ccticketpricechannel_override` (Float) is derived by
  `trg_update_cctktprc_override` → `update_ccticketpricechannel_ovr()`, which
  strips `$` (`''` → NULL) and rewrites the text as `'$' || text`.

`update_price_band` then recomputes `cc_price_band` / `sty_price_bands`.
Separately, the valid-values table can never hold NULL key/value: darwin's
`IdentTuple` rejects them with a 500. The Vertica → PG export turns `''` into
NULL (unquoted empty + `\copy CSV`), so text columns where blank matters
need a post-load `NULL → ''` repair.

**Functional:**
- **Ticket Price** is the planned tag (list) price per style color and
  channel.
- **Ticket Price Override** lets the planner replace that price for a channel
  without changing the original.
- **Final Ticket Price** is the override if one is set, otherwise the Ticket
  Price. It is calculated in the viewdefn and not stored.

The override is a dropdown of approved price points from the brand's price
band lookup, not a free-typed number. This stops planners entering
off-ladder prices like 147.37. Setting an override also moves the style
color's and style's price band. If the override doesn't save, the plan,
price band and downstream margin numbers keep using the original ticket
price.

## Gotchas

- **Detection tip for "edit doesn't save, no error":** for every editable
  `validValues` column, compare the M_Meta `type` of the attribute in
  `dataApi …ids=` with the one in `dataIndex`. A Float/Int list feeding a
  String column, or the reverse, is this bug. Confirm it with the darwin log
  line `failed to cast input for column`, or with the `lifecycleParams`
  request payload: a bare number where text is expected.
- **Detection tip for a dropdown 500 or one that stays on "Loading…":**
  `SELECT attributeid, count(*) FROM <brand>_v_memberbasedvalidvalues WHERE
  attributekey IS NULL OR attributevalue IS NULL GROUP BY 1;`. Any row means
  darwin's `Tuple has null` error for that attribute. You can also open
  `/api/attribute/validValues/one?appName=Assortment&ids=<attr>` directly in a
  logged-in browser. A Float list returns `"id": 149.0` and a String list
  returns `"id": "149.00"`.
- **Pointing a dropdown at a list no screen has used before can surface
  latent data bugs.** Test the new `validValues` URL on its own before
  calling a config fix done.
- **`lifecycleParams` is the Style Edit save call** for `planningParams` and
  lifecycle sections, so don't read "only lifecycleParams fired" as "nothing
  was sent". Also, since frontend commit `f4d78a366` (2026-08-12),
  `validValues` dropdowns save only when an option is selected. Clicking
  outside the field does not save.
- **The `text` renderer only works here because the trigger stores the `$`.**
  An override saved without the `$` prefix by any route other than the UI
  trigger would display without it. Check with
  `… WHERE ccticketpricechannel_override_txt NOT LIKE '$%'`.
- **"$NaN" or "NaN%" elsewhere in Style Edit** (any client, any empty
  money/percent cell) is the same frontend regression from INT-6200
  (`33d4e8f53`), not a data problem. Boden's per-currency override columns
  (`nullable: true` with the `pound`/`euro` renderers) are likely affected.
  That is inferred and has not been checked in Boden QA. The config
  `renderer: "text"` change only covers KW's override field.
- **This design is KW-only.** Belk and Boden store their ticket-price
  overrides directly as Float and edit them as numbers. Only the four KW
  brands have the `_txt` + `trg_update_cctktprc_override` pattern
  (`knowledge/db-trigger-matrix.md`). So the line-36 fix doesn't need porting
  to other clients.
- **`sty_size_concept_types`** also had a NULL blank row in LOFT QA. It
  comes from the inbound size-concept lookup feed, not an ETL-added blank,
  and is filtered by department. The ETL change cleans it up as well, but no
  screen symptom was tied to it.
- **ETL PR base:** the ETL `SUP-4786` branches were cut from
  `etl_assortment_planning_upgrade`. Comparing them with
  `etl_assortment_planning` shows 30+ unrelated commits.
